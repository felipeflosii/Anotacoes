# Template — Pitch Deck

tags: #template #pitch #apresentação #slides
links: [[10 - Anatomia de um Pitch]] | [[11 - Storytelling do Projeto]] | [[12 - Apresentação Visual]]

---

> Use como roteiro de conteúdo para montar os slides.
> Cada bloco = 1 slide (ou 2 no máximo).
> Nomeie a versão final como: `Pitch - [Nome do Projeto] - v[versão]`

---

## SLIDE 1 — CAPA

```
Elemento central: Nome do projeto (fonte grande, impacto visual)
Subtítulo: tagline de 1 frase (o que o projeto faz em 10 palavras)
Rodapé: Time | Data | Contexto (ex: FIAP — Challenge 2025)

Exemplo de tagline:
"O app que distribui tarefas de grupo sem que ninguém precise ser o chato."
```

---

## SLIDE 2 — O GANCHO

```
Objetivo: fazer a banca parar e prestar atenção nos próximos 30 segundos

Opção A — dado chocante:
"[X]% dos alunos já tiveram nota rebaixada por causa de trabalho em grupo."

Opção B — pergunta que toca:
"Levanta a mão quem nunca foi prejudicado por um colega de grupo que sumiu."

Opção C — história de 3 linhas:
"Era segunda, 23h, 3 dias antes da entrega.
Maria abre o WhatsApp e percebe: das 8 tarefas combinadas, 1 foi feita.
O grupo tinha se reunido 4 vezes."

Dica de design: 1 frase grande + imagem que reforça a emoção.
```

---

## SLIDE 3 — O PROBLEMA

```
Conteúdo:
- Quem sofre: [público específico]
- O que acontece: [situação concreta]
- Impacto: [o que isso causa na vida deles]
- Dado: [evidência de escala ou urgência]

Dica: máximo 4 bullet points. Prefira 1 estatística + 1 frase de contexto.

Exemplo de estrutura visual:
[Ícone] Problema 1 — [frase curta]
[Ícone] Problema 2 — [frase curta]
[Ícone] Problema 3 — [frase curta]
```

---

## SLIDE 4 — AS ALTERNATIVAS ATUAIS (opcional, mas poderoso)

```
Objetivo: mostrar que você pesquisou e sabe por que as alternativas falham

Formato sugerido:
Tabela simples com colunas: Alternativa | O que fazem | O que falta

Ou: "As pessoas tentam resolver com [A], [B] e [C] — mas nenhum resolve [X]."

Dica: não ataque os concorrentes. Mostre onde há lacuna.
```

---

## SLIDE 5 — A SOLUÇÃO

```
Conteúdo:
- Nome do projeto em destaque
- 1 frase de posicionamento: "[Nome] é um(a) [tipo] para [quem] que [benefício]."
- Imagem do produto (print, mockup, protótipo)

Dica: a imagem do produto faz mais do que qualquer descrição.
Se não tem produto ainda: use o protótipo do Figma, um wireframe ou storyboard.
```

---

## SLIDE 6 — COMO FUNCIONA

```
Formato: 3 passos simples

Passo 1: [ação do usuário] → [o que acontece]
Passo 2: [ação do usuário] → [o que acontece]
Passo 3: [resultado final]

Ou: fluxo visual com telas reais do produto clicadas em sequência.

Dica: simplifique. A banca não precisa entender tudo — precisa entender o conceito.
```

---

## SLIDE 7 — DEMONSTRAÇÃO

```
Não é um slide — é um momento ao vivo.

Opções:
1. Demo ao vivo (protótipo Figma ou MVP real) — melhor opção
2. Vídeo de 60 segundos mostrando o fluxo principal
3. GIF animado das principais telas
4. Sequência de prints com narração

Preparação:
- Teste no projetor ou tela da banca 30 min antes
- Tenha backup (vídeo) se a demo ao vivo travar
- Ensaie o roteiro da demo — siga um fluxo, não explore aleatoriamente
```

---

## SLIDE 8 — MERCADO / IMPACTO

```
Para projeto acadêmico / social:
- Quantas pessoas se beneficiariam?
- Qual indicador de impacto você usaria para medir sucesso?

Para projeto com modelo de negócio:
- TAM: [número] pessoas têm esse problema
- SAM: [número] podemos alcançar com nossos recursos
- SOM: [número] meta realista no primeiro ano
- Receita potencial: R$ [projeção]

Dica: 1 número grande + contexto. Não liste 10 estatísticas.
```

---

## SLIDE 9 — DIFERENCIAIS

```
Formato: tabela de comparação

| Critério         | [Nosso projeto] | Alternativa A | Alternativa B |
|------------------|----------------|--------------|--------------|
| [diferencial 1]  | ✅             | ❌           | ❌           |
| [diferencial 2]  | ✅             | ✅           | ❌           |
| [diferencial 3]  | ✅             | ❌           | ✅           |
| [diferencial 4]  | ✅             | ❌           | ❌           |

Dica: escolha os critérios onde vocês ganham.
Seja honesto — se a alternativa faz algo melhor, reconheça.
```

---

## SLIDE 10 — TIME

```
Conteúdo:
- Foto de cada membro (informal funciona melhor que foto de documento)
- Nome + 1 linha de credencial relevante para o projeto

Exemplos de linha de credencial:
"[Nome] — 2 anos em desenvolvimento web, entregou 3 projetos na FIAP"
"[Nome] — vive o problema como usuário há 3 semestres, entrevistou 12 pessoas"
"[Nome] — design UX, criou o protótipo em 48h durante o hackathon X"

Dica: conecte as credenciais ao projeto, não ao currículo geral.
```

---

## SLIDE 11 — PRÓXIMOS PASSOS / CHAMADA PARA AÇÃO

```
Para banca acadêmica:
"Pedimos aprovação para [próxima fase / nota máxima] com base em [critérios cumpridos]."

Para investidor / cliente:
"Estamos buscando [recurso / parceria / aprovação].
Podemos agendar [reunião de alinhamento / piloto / próxima conversa]?"

Para pitch de competição:
"[Nome do projeto] está pronto para [etapa seguinte].
Contamos com o apoio de vocês para [ação específica]."

Dica: termine com ação — não com "obrigado". O obrigado vem depois da ação.
```

---

## SLIDE 12 — OBRIGADO + CONTATO

```
Nome do projeto
[e-mail de contato do time]
[link do projeto / GitHub / Figma / landing page]
[QR code para acessar ao vivo, se aplicável]

"Ficamos à disposição para perguntas."
```

---

## Checklist antes de apresentar

```
[ ] Todos os slides revisados pela última vez com olhos frescos
[ ] Ortografia e gramática verificadas
[ ] Demo ao vivo testada no equipamento que será usado
[ ] Backup da demo (vídeo) disponível
[ ] Quem fala cada slide está definido e ensaiado
[ ] Tempo total cronometrado (deve caber no tempo dado)
[ ] Perguntas difíceis ensaiadas (veja [[10 - Anatomia de um Pitch]])
[ ] Todos os membros chegam 15 min antes
```
