## Por que feedback é uma habilidade técnica

Feedback mal dado cria defensividade, ressentimento e piora a performance. Feedback bem dado acelera o crescimento e fortalece a confiança.

> A qualidade do feedback de um Tech Lead ou coordenador define a velocidade de evolução do time.

---

## O modelo SBI — Situação, Comportamento, Impacto

É o framework mais adotado no mercado para feedback construtivo.

```
Situação:    "Na daily de ontem..."
Comportamento: "...quando você disse que a feature estava pronta, mas ela ainda não tinha testes..."
Impacto:     "...o time planejou o sprint seguinte contando com essa entrega e precisamos reajustar tudo."
```

**Por que funciona:**
- Foco em comportamento observável, não em julgamento de caráter
- Cita situação específica, não generaliza ("você sempre...")
- Conecta ao impacto real, não à emoção de quem fala

---

## Feedback positivo também precisa de especificidade

❌ Fraco: "Você fez um ótimo trabalho!"
✅ Forte: "A forma como você documentou os endpoints da API antes de implementar poupou pelo menos 3h de retrabalho do Bruno. Isso foi exatamente o tipo de iniciativa que o time precisa."

---

## Como receber feedback

| Reação natural | Reação produtiva |
|---|---|
| Defender ou justificar imediatamente | Escutar até o fim antes de responder |
| Minimizar ("não foi bem assim...") | Perguntar para entender melhor |
| Contra-atacar | Agradecer, mesmo que discorde |
| Ignorar | Registrar e refletir antes de decidir |

---

## Feedback em code review

Code review é uma forma de feedback técnico. As mesmas regras se aplicam:

```
❌ "Esse código está errado."
✅ "Nessa função, se o array vier vazio, vai lançar uma exceção
    na linha 42. Sugiro adicionar um guard clause no início.
    O que acha?"

❌ "Por que você fez isso assim?"
✅ "Optei por esse approach porque... Você considera outra
    alternativa? Curioso para entender seu raciocínio."
```
