Cloud Service Models

Entendendo as camadas de abstração em nuvem: IaaS, PaaS, DBaaS, SaaS e Serverless.

O Paradigma da Abstração

A computação em nuvem opera na transferência de responsabilidade. Quanto maior o nível do serviço, menos controle direto você tem sobre o sistema operacional e infraestrutura física, permitindo foco exclusivo no desenvolvimento do código e modelagem de negócios.

1. IaaS (Infrastructure as a Service)

No modelo IaaS, o provedor entrega os blocos de construção fundamentais: instâncias de computação brutas, redes virtuais e volumes de armazenamento. A abstração ocorre apenas no hardware físico (hypervisor). Você é integralmente responsável por provisionar, configurar e aplicar patches no sistema operacional, além de instalar middlewares e gerenciar o runtime.

Este modelo é ideal quando o projeto exige acesso root/admin para rodar softwares legados ou tunning agressivo no kernel do SO.

bashIaaS - Provisionamento de Máquina Virtual
# Criando um ambiente Linux cru (IaaS). 
# A partir deste ponto, o SSH, firewall interno e runtimes (Bun, Java, Python) são sua responsabilidade.
az vm create   --resource-group rg-infra   --name linux-dev-env   --image UbuntuLTS   --admin-username adminuser   --generate-ssh-keys

2. PaaS (Platform as a Service)

O PaaS eleva a abstração escondendo o sistema operacional e o middleware. O ambiente de execução (runtime) é pré-configurado pelo provedor. O objetivo é receber o seu código-fonte, construir os artefatos e expor a aplicação através de um endpoint seguro. Rotinas de balanceamento de carga e auto-scaling são configurações declarativas, não operacionais.

Plataformas como Vercel atuam como um PaaS altamente especializado em frontend, gerenciando o deploy de projetos React/Vite de forma transparente diretamente do repositório Git, distribuindo os assets na edge network.

bashPaaS - Deploy de Código
# O provedor cuida da infraestrutura subjacente.
# O foco é puramente entregar o artefato da aplicação.
vercel --prod

# Ou no contexto Azure (App Service para Spring Boot / FastAPI):
az webapp up   --resource-group rg-backend   --name api-service-prod   --runtime "JAVA|21-java21"

3. DBaaS (Database as a Service)

Subcategoria do PaaS estritamente focada em persistência de dados. Em vez de subir uma instância Linux (IaaS) e instalar manualmente um PostgreSQL, o provedor oferece o motor do banco de dados pronto para uso. O Data Plane (arquivos de log, buffer pool, processos em background) e o Control Plane (backups PITR, failover, replicação síncrona) são opacos para o desenvolvedor. A interface de interação restringe-se à connection string e DDL/DML.

4. Modelos Adicionais: FaaS e SaaS

FaaS (Function as a Service) / Serverless: Uma granularidade ainda maior que o PaaS. Em vez de hospedar uma aplicação inteira aguardando requisições, você implanta blocos de código (funções) vinculados a eventos (triggers). A computação só existe durante a execução do código (milissegundos) e escala de zero a milhares de instâncias instantaneamente. Ex: AWS Lambda, Azure Functions.

SaaS (Software as a Service): O nível mais alto de abstração. O provedor gerencia toda a pilha de tecnologia, e você consome o software final como usuário ou administrador lógico. Você não altera o código-fonte nem gerencia a infraestrutura. Ex: GitHub, Gmail, Office 365.
