Azure SQL Database (DBaaS)

Guia prático de provisionamento via Azure CLI, políticas de firewall e conectividade com Spring Boot 3 e FastAPI.

Conceito de DBaaS

Database as a Service (DBaaS) abstrai a infraestrutura hospedeira. Diferente de gerenciar um PostgreSQL ou SQL Server em uma máquina virtual (IaaS), no DBaaS o provedor administra sistema operacional, replicação, backups automáticos e patches de segurança. A responsabilidade técnica se concentra na modelagem do database, índices e na estruturação lógica do backend.

1. Criação do Azure SQL Database

O provisionamento no Azure exige a criação prévia de um servidor lógico (um container de administração para múltiplos bancos) antes de instanciar o database. A camada recomendada para a maioria das REST APIs modernas é a vCore Serverless, pois escala computação dinamicamente e pode pausar em ociosidade, minimizando custos. A alternativa legada, DTU, provisiona pacotes fixos de recursos.

bashAzure CLI — Provisionamento
# 1. Criar o Resource Group
az group create \
  --name rg-backend-db \
  --location eastus

# 2. Criar o Servidor Lógico SQL
az sql server create \
  --name server-sql-dev \
  --resource-group rg-backend-db \
  --location eastus \
  --admin-user "dbadmin" \
  --admin-password "S3nh@F0rt3!"

# 3. Criar o Database na camada Serverless (vCore)
az sql db create \
  --resource-group rg-backend-db \
  --server server-sql-dev \
  --name db_production \
  --edition GeneralPurpose \
  --compute-model Serverless \
  --family Gen5 \
  --capacity 2 \
  --min-capacity 0.5 \
  --auto-pause-delay 60

2. Configuração de Rede e Conectividade

Por segurança, o Azure SQL rejeita requisições externas por padrão. É necessário configurar regras de firewall baseadas em IP para liberar o tráfego do seu ambiente Linux local ou habilitar a flag AllowAllWindowsAzureIps para permitir que aplicações dentro do Azure (como Vercel via integrações ou App Services) acessem o endpoint.

bashAzure CLI — Regras de Firewall
# Obter o IP público da sua máquina (requer curl)
MEU_IP=$(curl -s ifconfig.me)

# Liberar acesso para o seu IP local
az sql server firewall-rule create \
  --resource-group rg-backend-db \
  --server server-sql-dev \
  --name AllowLocalIP \
  --start-ip-address $MEU_IP \
  --end-ip-address $MEU_IP

# Habilitar acesso de outros serviços internos do Azure (opcional)
az sql server firewall-rule create \
  --resource-group rg-backend-db \
  --server server-sql-dev \
  --name AllowAzureServices \
  --start-ip-address 0.0.0.0 \
  --end-ip-address 0.0.0.0

3. Integração com Backend

A connection string do Azure SQL utiliza a porta padrão 1433 e exige conexão via TLS (Encrypt=True). Seguem exemplos de integração considerando padrões de Clean Architecture com frameworks distintos.

Spring Boot 3 + Java 21

Configuração do application.yml no pacote de infraestrutura para acesso via Spring Data JPA.

yamlapplication.yml
spring:
  datasource:
    url: jdbc:sqlserver://server-sql-dev.database.windows.net:1433;database=db_production;encrypt=true;trustServerCertificate=false;hostNameInCertificate=*.database.windows.net;loginTimeout=30;
    username: dbadmin
    password: S3nh@F0rt3!
    driver-class-name: com.microsoft.sqlserver.jdbc.SQLServerDriver
  jpa:
    hibernate:
      ddl-auto: update
    show-sql: true
    properties:
      hibernate:
        dialect: org.hibernate.dialect.SQLServerDialect

FastAPI + Python

String de conexão otimizada para SQLAlchemy ou SQLModel via driver pyodbc.

pythondatabase.py
import urllib.parse
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

server = 'server-sql-dev.database.windows.net'
database = 'db_production'
username = 'dbadmin'
password = 'S3nh@F0rt3!'
driver = '{ODBC Driver 18 for SQL Server}'

params = urllib.parse.quote_plus(
    f'Driver={driver};Server=tcp:{server},1433;Database={database};Uid={username};Pwd={password};Encrypt=yes;TrustServerCertificate=no;Connection Timeout=30;'
)

SQLALCHEMY_DATABASE_URL = f"mssql+pyodbc:///?odbc_connect={params}"

engine = create_engine(SQLALCHEMY_DATABASE_URL)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)

4. Limpeza de Recursos

Desalocação

Após testes e implementações de desenvolvimento, exclua o Resource Group para evitar cobranças remanescentes de armazenamento, mesmo na camada Serverless.

bashAzure CLI — Cleanup
# Remove o servidor lógico, database e regras de firewall em cascata
az group delete --name rg-backend-db --yes --no-wait

Glossário Técnico

Termo Definição
PaaSPlatform as a Service. Modelo focado na entrega da plataforma de execução (como o DBaaS), isentando o desenvolvedor da gerência do S.O.
vCore ServerlessTier computacional do Azure SQL que aloca CPU sob demanda e pausa instâncias inativas automaticamente.
Logical ServerNo Azure SQL, é o invólucro de gestão que unifica bases de dados e regras de segurança (Firewall, Defender) sob o mesmo FQDN.
Connection StringString estruturada contendo endpoint, porta, driver e credenciais enviada no payload de inicialização do ORM.
pyodbcDriver nativo recomendado para integrar aplicações Python (FastAPI/SQLAlchemy) aos bancos de dados SQL Server via protocolo ODBC.
